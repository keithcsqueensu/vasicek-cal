# Tolerance register

Every numerical tolerance used by a test is listed here (D-016, ARCHITECTURE.md §7).

- **Values:** they live in one data file, `tests/tolerances.toml` (D-125).
- **C++ tests:** `tools/gen_tolerances.py` renders `tests/tolerances.hpp` from it. CI checks the
  header is current, and `tolerance_register_sync` fails if this page and the header list
  different ids.
- **Validation scripts:** they read the TOML directly and never parse C++.

Tests refer to tolerances by id, never by literal. A value is changed only in the TOML, with its
reason recorded on this page.

**Units.** "ulp" is the number of representable binary64 values between the computed result
and the mpmath reference, rounded once to binary64. That is a *relative* measure, so it
cannot hide a loss of relative accuracy the way an absolute bound can near zero.

**How values are set.** The worst error observed over the golden table, doubled and rounded
up. The observed figures come from the `note:` lines of the enforcing test. The headroom
covers libm differences between platforms (glibc vs the MSVC UCRT), which CI checks on
Linux (GCC 11, GCC 14, Clang 18) and Windows (MSVC). A tolerance may be raised only by
editing this file with a reason.

### The parity rule: what is claimed (D-118)

**Numerical precision: every period, every ρ tested.** The parity rule is within
`TOL_PARITY_MIXTURE_EPS` of mpmath on every golden case, including zero- and all-default periods
and ρ up to 0.99, and within `TOL_XREF_PERIOD_LL_EPS` (term-scaled) of ref on 4,296 further
points up to ρ = 0.9 and n = 10⁶. The worst absolute error in log L_t anywhere is 2.3e-10, on a
period whose terms are about 6.5e5 in size, i.e. rounding.

Before D-118, adaptive GH alone was used for zero- and all-default periods too, and those carried
no precision claim (D-116): 1.9e-5 absolute at ρ = 0.5 and 6.0e-3 at ρ = 0.9. The composite rule
removes that exclusion, so the separate materiality statement it needed is gone.

Each run still reports its own figures (D-092): the engine compares every period against the
doubled rule (GH 256, K = 32), flags any period above the D-120 threshold, and reports the
per-period maximum and the total. Multiplying both by 2 (1/`TOL_QUAD_CHECK_MIN_DETECTION_RATIO`)
bounds the true error; that factor is empirical (worst observed understatement 1.00002×), not
derived.

## Cross-reference, core vs ref (M1.7, M1.7b)

Four comparisons, four separately named tolerances, never interchangeable (D-107). Error scale
for per-period log-likelihoods: ε × max(1, abs(log C) + abs(log I)). l_t = log C + log I can
cancel heavily (n = 10⁶, d = 350,000: terms of ±6.5e5, sum −15), and both engines then carry about
ε·6.5e5 absolute error, confirmed with mpmath.
